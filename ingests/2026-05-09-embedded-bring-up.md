# 임베디드 프로젝트 개발 과정과 브링업(Bring-up)

임베디드 개발, 특히 제품 개발 관점에서의 전체적인 사이클과 그 중 가장 초기 단계인 '기획'과 '브링업'에 대해 설명한 글.

## 핵심 요약
- **임베디드 개발 과정**: 기획(부품 산정) -> 보드 브링업 -> SW 안정성 확보 -> 인증 테스트 -> 출시 -> 유지보수
- **기획 단계의 중요성**: 프로젝트의 첫 단계는 코딩이나 브링업이 아닌 부품 선정 및 스펙 검토. 부품의 스펙, 드라이버 지원 여부, 리스크 등을 초기에 면밀히 검토하지 않으면 개발 도중 큰 어려움을 겪을 수 있음 (예: 메모리와 SoC 간의 호환성 문제 등).
- **브링업(Bring-up)**: 부팅이 되지 않는 깡통 보드를 받아 기본 동작을 하는 수준(OS 부팅 및 기본 드라이버 구동)까지 살려내는 작업. '기계에 생명을 불어넣는' 과정.
- **브링업의 실제**:
  - 부트로더, 커널, 시스템 이미지를 빌드하여 TRACE32 같은 하드웨어 장비나 제조사 툴로 다운로드.
  - 전원 인가 시 스타트업 코드(어셈블리) 실행 -> 부트로더 -> 커널 -> 유저 라이브러리 로딩 순으로 진행.
  - UART 로그나 하드웨어 디버거를 통해 부팅 과정을 모니터링하며 크래시나 드라이버 초기화 에러를 해결.
  - 한 번에 부팅될 확률은 매우 낮으며, 이 과정에서 잦은 에러 해결과 야근이 동반되는 경우가 많음.
